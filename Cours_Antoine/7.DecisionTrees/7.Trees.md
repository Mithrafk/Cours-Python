## Les arbres de décision

### La structure :
- Des données avec ses features
- des règles de décisions basé sur une séparation linéaires sur une catégorie

- Noeud : Test / Regles de décision => Features
- Branches : Condition rempli du noeud => attribut value
- Feuilles : target (ce que je veux predire => Classification)

### Trouver le meilleur modèle/arbre  
Impossible d'explorer tout les arbres (beaucoup trop de combinaisons possibles)  

**Compléxité d'un arbre**  
- Profondeur de l'arbre
- Nombres de feuilles (et d'individus par feuille)
- Nombres de noeud (tests)
- Espérance du nombre de tests (sur les examples selon la distribution cible)  

$==>$ On veut l'arbre qui discrimine le mieux les données en un nombre minimal de test. En moyenne on veut avoir peut d'étapes de discrimination (mais si rarement on à 2/3x plus de tests ca va ?)

**Solution euristique pour trouver un bon arbre** :
Première étape (premier test) : On cherche le meilleur test qui donne le plus gros gain d'info sur les sous-populations.
2nd étape : On recommence ca sur chaque sous population crée  
$->$ Algorithme glouton/myope, mais pas possible de faire mieux pour explorer les combinaison de cette manière  
On accepte les décisions même si ce n'est pas homogène (on a 2 classes dans la feuille, et on prédit le majoritaire).  
On a aussi de l'élagage (pré ou post train). On va utiliser des méthodes stats qui nous disent si le gain d'info est significatif ou non et supprimer des branches inutiles pour éviter un arbre toufu

**Trouver la feature idéale pour décider MTN : Entropie ($I$)**

On regarde entropie avant et celle des n sous-pop après décision. On va préféré le descripteur avec ce seuil qui donne l'entropie minimale.  
$$ \sum{\alpha_1<ent_1> + \alpha_2<ent_2>}$$
$$ Entropie : I = -\sum_{i : classes}{p_i * log(p_i)}$$
avec :
- pi : proportion de classe i dans le sous ensemble  

**Fonction Gain :**
$$
Gain(S,A) = I(S) - \sum_{V\in valeurs(A)}{ \frac{|S_V|}{|S|} . I(S_V)}  
$$

**Fonction Gini :**
Alternative à la fonction
$$
Gini(D) = 1 - \sum{(p_j)**2}
$$

### Problème de généralisation :  
Pour éviter l'overfitting, on va faire de l'élagae (pruning) :
- Pré-elagage : lors de la descente, on regarde si le gain est utile, sinon on s'arrete (evite le glouton, mais n'assure pas qu'on n'a pas raté de noeud plus profond interessant)
- Post-elagage : On fait l'arbre en entier, puis on remonte en supprimant les noeuds inutiles (plus glouton, mais assure de tout voir, on a donc une méthode plus certaines ?)

### Bilan arbres :  
**Avantages :**
- interprétable : selection automatique de variables pertinentes et lisible en clair des regles de decision
- Non paramétrique : Pas de prbl du type de variable et prbl d'échelle. Robustes faces aux données aberrantes / manquantes

**Inconvénients :**
- Prbl de stabilité sur petites bases de données (feuilles à petit effectifs)
- Méthode gloutonne et myope (prbl pour identifier interactions entre les variables)
