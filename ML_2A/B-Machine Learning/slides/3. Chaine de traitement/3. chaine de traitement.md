## 1. Introduction à la chaîne de traitements

La chaîne de traitements (pipeline) est le processus par lequel les données brutes sont transformées avant d'être fournies à un algorithme d'apprentissage. 
L'objectif est de comprendre et mettre en œuvre les principaux leviers de performances en machine learning (notamment via `scikit-learn`).

> 💡 **Idée clé** : La performance d'un modèle dépend souvent davantage de la qualité des données et des pré-traitements (Feature Engineering) que de l'algorithme lui-même.

---

## 2. Gestion des valeurs manquantes

Les valeurs manquantes sont fréquentes dans les jeux de données réels et sont souvent localisées sur une ou quelques colonnes spécifiques.

> 📝 **Tes notes** : Attention au type de valeurs : un "?" représentant une valeur manquante peut forcer l'outil à lire toute la colonne comme du texte (`str`) au lieu de nombres.

### 2.1 Valeurs continues
Plusieurs stratégies existent pour gérer les "trous" dans les données continues :

| Stratégie | Description | Avantages / Cas d'usage |
| :--- | :--- | :--- |
| **Suppression** | Retirer les lignes ou les colonnes contenant des NaN. | 📝 **Tes notes** : À faire si la colonne a trop de NaN. Simple, mais perte d'informations. |
| **Valeur arbitraire** | Remplacer par une constante (ex: -999). | Permet aux modèles basés sur les arbres d'isoler ces cas. |
| **Interpolation / Statistique** | Remplacer par la moyenne ou la médiane. | 📝 **Tes notes** : La médiane est préférable car elle écarte l'influence des valeurs aberrantes (outliers). |
| **Modélisation** | Algorithmes prédictifs (k-Plus Proches Voisins, Expectation-Maximization - EM). | 📝 **Tes notes** : Carrément faire un modèle pour générer (prédire) ces valeurs. Plus précis. |

### 2.2 Valeurs discrètes (catégorielles)
Pour les variables catégorielles manquantes, les approches sont légèrement différentes :
- **Valeur la plus fréquente** (Mode).
- **Échantillonnage multinomial** (tirage aléatoire basé sur la distribution des autres valeurs).
- **Plus proche voisin** (K-NN basé sur les autres caractéristiques de l'individu).
- **Prédicteur** (entrainer un classifieur pour deviner la catégorie manquante).

## 3. Ingénierie des caractéristiques (Feature Engineering)

Le Feature Engineering consiste à créer, modifier ou simplifier les variables (features) pour aider le modèle à mieux apprendre.

> 📝 **Tes notes** : On veut "virer" les variables discrètes textuelles (ex: "Homme | Femme" en `str` = chiant => 0 | 1).

### 3.1 Encodage des variables discrètes
Les algorithmes mathématiques ont besoin de nombres, pas de texte.

*   **Cas Binaire** : Remplacement direct (ex: `Male` = 0, `Female` = 1).
*   **Cas N-aire (Multiple)** : Utilisation du **One-Hot Encoding**.
    > 📝 **Tes notes** : "RGB" : 0|1|2 est impossible car ça induirait un ordre ou une hiérarchie fausse. => OneHotEncoding crée 3 nouvelles colonnes avec Oui|Non (1 ou 0) sur chaque couleur.
*   *Option* : Regrouper les catégories très peu fréquentes dans une catégorie "Autre" (ex: dans scikit-learn `OneHotEncoder(min_frequency=6, sparse=False)`).

> 🔎 **Complément** : L'ouverture vers le **Deep Learning** permet l'apprentissage automatique de représentations (Representation Learning). Au lieu d'un One-Hot, on utilise des **Embeddings** (plongements) qui calculent une distance sémantique continue entre les mots, les utilisateurs, ou des concepts visuels.

### 3.2 Simplification des données
> 📝 **Tes notes** : Il faut toujours visualiser les données avant de travailler pour comprendre. Se fier à son instinct sur ce qui marche le mieux après visualisation.

*   **Binarisation** : Transformer une variable continue en binaire (ex: si un pixel est > 0, alors 1, sinon 0).
*   **Discrétisation** : Découper une variable continue en "bacs" (bins) ou intervalles (quantiles ou linéaires). Utile pour modéliser des effets non linéaires de manière simple.

*Exemple du cours (Le damier / Checkers)* : Un classifieur linéaire classique échoue à séparer des classes réparties en damier (score CV ~0.5). Si on crée de nouvelles caractéristiques (intervalles binaires pair/impair sur les dimensions), le classifieur linéaire monte à un score de CV de ~0.85 !

### 3.3 Transformations arbitraires / expert métier
Utiliser la connaissance du domaine pour créer des caractéristiques plus pertinentes que les données brutes.

> 📝 **Tes notes** : 
> - Ramener les données à une mesure adaptée (passage au log, exponentielle, etc.) peut aider le modèle.
> - Rajouter des colonnes combinées : ex. si j'ai `largeur` et `longueur`, créer une colonne `surface = largeur x longueur` si la surface est une question importante dans mon problème.

### 3.4 Target Encoding
Consiste à remplacer une catégorie par la moyenne de la variable cible (Y) pour cette catégorie. (ex: si la catégorie `Private` a 33% de chance d'avoir la cible à 1, on remplace `Private` par 0.33).

> 🚩 **Piège fréquent** : Le Target Encoding est très puissant mais très dangereux. Il y a un énorme risque de **fuite de données (Data Leakage)** si on calcule cette moyenne sur l'ensemble du jeu de données (y compris le jeu de test) ou sans utiliser de techniques de lissage/validation croisée stricte. 📝 **Tes notes** confirment : "Sources de nombreux problèmes (fuite de données)".

## 4. Normalisation des données

La normalisation consiste à ramener les différentes variables à des échelles comparables.

**Pourquoi normaliser ?**
1. Pour améliorer les performances en tirant parti d'informations à différentes échelles.
2. Pour faciliter et accélérer le réglage des hyper-paramètres (mêmes ordres de grandeur = mêmes réglages par défaut).
3. Pour respecter les propriétés mathématiques du modèle utilisé.

### 4.1 Normalisation Standard (Gaussienne / Z-score)
Elle centre la variable (moyenne = 0) et la réduit (écart-type = 1). À tester systématiquement (présent dans tous les frameworks).

L'équation pour une variable $j$ et un individu $X$ :
$$ Z_j = \frac{X_j - \mu_j}{\sigma_j} $$

*   $Z_j$ : Valeur normalisée.
*   $X_j$ : Valeur brute initiale de la caractéristique $j$.
*   $\mu_j$ : Moyenne empirique de la caractéristique $j$.
*   $\sigma_j$ : Écart-type empirique de la caractéristique $j$.

> 📝 **Tes notes** : 
> - **Obligatoire** pour l'entrée des réseaux de neurones (et les algorithmes basés sur des distances comme KNN ou SVM).
> - **Inutile** pour les modèles basés sur les arbres (Arbre de décision, Random Forest, Gradient Boosting) car leurs scissions ne dépendent que de l'ordre des valeurs.
> - **Contrepartie** : On perd une part d'information directe (l'échelle originelle métier).

### 4.2 La normalisation par individus (par lignes)
Au lieu de normaliser chaque caractéristique (colonne) indépendamment, on normalise chaque individu (ligne) par rapport à lui-même. C'est lié à la nature des données.

> 📝 **Tes notes** : On normalise les lignes principalement pour le traitement de texte (NLP), les séries temporelles, ou les signaux.

**Exemples de normalisation par individu :**
*   **Min-Max individuel** : 
    $$ \tilde{x}_i = \frac{x_i - \min(x_i)}{\max(x_i) - \min(x_i)} \in [0, 1] $$
*   **Multinomiale (Somme à 1)** :
    Utile si le signal est strictement positif (ex: probabilités, intensités).
    $$ \tilde{x}_{ij} = \frac{x_{ij}}{\sum_k x_{ik}} $$
    Conditions : $\tilde{x}_{ij} \in [0, 1]$ et $\sum_j \tilde{x}_{ij} = 1$
*   **Produits scalaires / Norme $L_2$** :
    $$ \tilde{x}_{ij} = \frac{x_{ij}}{\sqrt{\sum_k x_{ik}^2}} $$
    Condition : $\| \tilde{x}_i \|_2 = 1$ (La somme des carrés vaut 1).

*Cas pratique : Classification de signaux*
Il faut se demander quelles propriétés d'invariance on recherche :
- Détection indépendante de l'échelle ? -> Normalisation Min-Max.
- Somme à 1, ou moyenne nulle ?
- Invariance en translation ? -> Transformation dans le domaine fréquentiel (FFT, PSD).

## 5. Conclusion et Approche Standard

La méthode classique de bout en bout en Machine Learning :
1. **Traitements bruts** : Interprétation des informations expertes/métiers.
2. **Batteries de tests classiques** : Estimer rapidement les performances de base.
   - Normalisation standard
   - Modèles de base (Linéaire + Forêts aléatoires)
   - Validation croisée rigoureuse.
3. **Optimisation** :
   - Feature engineering (itération).
   - Grid-search (Recherche d'hyper-paramètres).
   - Ensembling (Combinaison de modèles).

> 💡 **Idée clé** : Beaucoup d'outils existent déjà dans `scikit-learn`. La maîtrise passe par la lecture de la documentation. S'il manque un outil spécifique, il faut penser à le coder et l'intégrer au pipeline.

## 6. Pièges à éviter

- 🚩 **Variables textuelles cachées** : Un caractère non numérique (`?`, `NA`, espace) dans un fichier CSV peut transformer toute une colonne de valeurs continues en type "Texte/String". À vérifier lors de l'import (cf. tes notes).
- 🚩 **One-Hot Encoding incomplet** : Ne pas grouper les catégories très rares peut mener à des centaines de colonnes inutiles qui feront "overfitter" le modèle (fléau de la dimensionnalité).
- 🚩 **Data Leakage via Target Encoding** : Utiliser la Target pour encoder une feature sur tout le dataset (Train + Test) triche sur le score de validation. L'encodage ne doit être calculé *que* sur le Train.
- 🚩 **Normaliser avant de spliter** : Ne jamais calculer $\mu$ et $\sigma$ sur l'ensemble complet avant séparation Train/Test (Data leakage). Toujours calculer les statistiques de normalisation sur le Train, et les appliquer sur le Test.
- 🚩 **Normaliser pour des Forêts** : Perdre du temps et des ressources à normaliser des données pour entrainer un Random Forest, ce qui est strictement inutile mathématiquement.

<details>
<summary><b>Question 2</b> : Qu'est-ce que le One-Hot Encoding et dans quel cas est-il absolument nécessaire face à une transformation numérique simple (0, 1, 2...) ?</summary>
<p>Le One-Hot Encoding transforme une variable catégorielle à N modalités en N colonnes binaires (0 ou 1). Il est obligatoire quand la catégorie n'a <b>pas d'ordre naturel</b> (ex: Rouge, Vert, Bleu). Si on utilisait 0, 1 et 2, le modèle déduirait faussement que Vert (1) est la moyenne mathématique entre Rouge (0) et Bleu (2).</p>
</details>

<details>
<summary><b>Question 3</b> : Quel est le danger principal du Target Encoding ?</summary>
<p>La <b>fuite de données (Data Leakage)</b>. Si on calcule la moyenne de la cible (Y) en incluant les données de l'ensemble de test, le modèle triche en apprenant indirectement la réponse attendue.</p>
</details>

<details>
<summary><b>Question 4</b> : Pour quel grand type d'algorithme la normalisation standard (Z-score) est-elle totalement inutile ?</summary>
<p>Les algorithmes basés sur les <b>arbres de décision</b> (Random Forest, Gradient Boosting, etc.). Leurs critères de séparation (ex: <i>"si X > 10"</i>) dépendent de l'ordre des valeurs, et l'ordre reste exactement le même avant et après normalisation.</p>
