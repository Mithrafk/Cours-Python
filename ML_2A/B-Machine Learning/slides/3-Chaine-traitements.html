2Valeurs manquantes

Variables continues

Les manques sont souvent localisés sur une (ou quelques) colonne(s). Options :

  • EM : estimation des données manquantes.
  • Estimer simplement les données (interpolation).
  • Supprimer les lignes affectées.
  • Affecter une valeur arbitraire : moyenne / médiane ; plus proche voisin.

Variables discrètes

  • La valeur la plus fréquente ; un échantillonnage (multinomial) ; le plus proche voisin (sur les autres caractéristiques) ; construire un prédicteur.

Imputer la puissance de la voiture 32

Les lignes 30 à 40 du jeu auto-mpg de la diapo 4 : la puissance (horsepower) de la voiture 32 est manquante (« ? »). Prédis : la moyenne des autres voitures est-elle une bonne estimation pour une 4 cylindres de 98 pouces cubes ?

Tes notes(1) « Attention aux types : "?" = valeur manquante peut conduire à un type str » : oui, une seule chaîne « ? » dans une colonne fait de toute la colonne un texte ; il faut déclarer « ? » comme valeur manquante à la lecture (na_values="?" dans pandas.read_csv, complément). (2) Trois options : virer la ligne, virer la colonne si trop de manquants, estimer : moyenne, puis médiane (qui écarte l’influence des valeurs aberrantes), voire un modèle qui prédit la valeur : c’est exactement la liste du cours (plus proche voisin, EM, prédicteur).

3Variables discrètes

Cas binaire / cas n-aire. Une couleur (Red, Red, Yellow, Green, Yellow) devient trois colonnes (Red, Yellow, Green) valant 0 ou 1 : c’est l’encodage one-hot. Option intéressante : grouper les catégories peu fréquentes : OneHotEncoder(min_frequency=6, sparse=False). Pour aller plus loin : ECoC (codes correcteurs d’erreur) et embedding.

One-hot avec regroupement des catégories rares

20 voitures de 5 couleurs, dont certaines très rares. Monte le seuil min_frequency : combien de colonnes restent ?

Tes notes« On veut virer les variables discrètes » : plus exactement, on veut les transformer en variables numériques (pas les supprimer). « Homme | Femme » se code 0 | 1 (cas binaire). « RGB : 0 | 1 impossible » : avec trois couleurs, un codage 0/1/2 inventerait un ordre (le vert « serait plus grand » que le rouge) ; le one-hot crée 3 colonnes Oui/Non. Complément : dans scikit-learn récent, le paramètre sparse a été renommé sparse_output ; la diapo utilise l’ancien nom.

4Ouverture vers le deep learning

« C’est quoi le deep learning ? » (réponse assez ouverte) : apprendre la meilleure représentation.

  • Apprendre des représentations (et des distances) entre éléments discrets : distance sémantique et/ou grammaticale entre les mots ; distance entre profils d’utilisateurs dans les systèmes de recommandation ; distance entre des graphes ou des nœuds de graphe.
  • Apprendre des représentations d’objets complexes : en vision, projeter les données dans un espace de faible dimension sémantique.
  • Des architectures génératives (GPT, Dall-e…) transférables d’une application à l’autre.
  • Architectures complexes : différents objectifs et modalités de données ; modélisation directe des contraintes métiers.

Conférence de référence : ICLR (International Conference on Representation Learning, d’après la diapo).

5Simplification des données

  • Binarisation : par exemple les pixels d’une image USPS, dont les histogrammes sont presque bimodaux (fond ou trait).
  • Discrétisation : par quantiles (même nombre d’exemples par intervalle) ou linéaire (même largeur), par exemple sur les colonnes d’auto-mpg.

Binariser et discrétiser

À gauche : un « pixel » presque toujours 0 ou grand ; choisis le seuil de binarisation. À droite : un attribut asymétrique ; compare des intervalles linéaires et des quantiles.

Tes notes« Visualiser les données avant de travailler pour comprendre. » C’est indispensable pour choisir un seuil de binarisation ou un nombre d’intervalles. « Cela permet d’introduire de nouveaux hyperparamètres (qu’on n’optimisera pas car trop lourd en calcul) : se fier à son instinct sur ce qui marche le mieux. » Oui : seuil de binarisation, nombre de quantiles sont des hyperparamètres de plus, et on les fixe souvent d’après l’histogramme plutôt que par grille de recherche.

6Transformations arbitraires / métiers

La diapo montre le jeu auto-mpg complet (mpg, cylinders, displacement, horsepower, weight, acceleration, model year, origin, car name) et pose : « Comment gérer la dernière colonne ? » (le nom de la voiture).

ComplémentLa colonne « car name » est du texte à très grande cardinalité (presque une valeur par ligne) : inutilisable telle quelle. Pistes : en extraire une caractéristique métier (la marque, premier mot du nom) puis la traiter comme une variable discrète (one-hot en regroupant les marques rares), ou l’ignorer.

Tes notes« Ramener les données à la mesure (log, exp…) peut aider le modèle. Rajouter des colonnes : combinaison de 2 colonnes (largeur × longueur = surface) si la surface est importante dans mon problème. » Oui : c’est l’intégration de la connaissance métier dans les caractéristiques. L’exemple qui suit le montre.

Exemple « checkers »

Des points d’un damier sur une grille de 5 × 5 cases. Avec un classifieur linéaire par défaut, les scores de validation croisée sont catastrophiques (≈ 0,5, 0,5, 0,3, 0,5, 0,4 : au niveau du hasard). En ajoutant des colonnes (intervalles binaires pair/impair sur les deux dimensions), les scores montent à ≈ 0,75–0,9 (d’après la diapo).

Le damier et les colonnes ajoutées

Un classifieur linéaire (régression logistique) sur différents jeux de colonnes, avec validation croisée à 5 plis. Prédis : les colonnes « pair/impair » suffisent-elles à séparer un damier ? De quelle colonne a-t-on encore besoin ?

La fuite du target encoding

Les étiquettes sont ici tirées au hasard, sans aucun lien avec la catégorie. Un bon modèle ne peut pas dépasser 50 % en test. Prédis : que va afficher le modèle en apprentissage quand chaque catégorie contient peu d’exemples ?

Tes notes« On encode la cible (y) dans chacune des variables prédictives : source de nombreux problèmes (fuite de données). » Oui : la variable explicative contient l’étiquette de l’exemple, surtout quand une catégorie n’a que quelques lignes. Complément (remède) : calculer l’encodage hors pli (pour chaque ligne, avec la moyenne des autres plis), ou lisser vers la moyenne globale.

8Normalisation

Pourquoi normaliser ? (par ordre d’usage)

  1. Améliorer les performances : tirer parti d’informations à différentes échelles.
  2. Faciliter le réglage des hyperparamètres : mêmes ordres de grandeur ⇒ mêmes réglages.
  3. Respecter les propriétés du modèle : par ex. hypothèse multinomiale ; modèles sans biais (normalisation des y).

Normalisation gaussienne (par variable)

Zj = (Xj − μj) / σj (centrer-réduire chaque colonne = « normalisation standard » de scikit-learn)

Un test à faire systématiquement (la fonction est implémentée dans tous les systèmes).

Qui souffre d’une échelle démesurée ?

Deux variables utiles (échelle 1) et une variable inutile d’échelle s. Trois modèles, avec et sans normalisation. Prédis : quel modèle ne s’en aperçoit pas du tout ?

La normalisation par individu (par ligne)

AttentionElle est liée à la nature des données (texte, signaux…).

min-max : x̃i = (xi − min(xi)) / (max(xi) − min(xi)) ∈ [0, 1] multinomiale : x̃i = xi / Σj xij ∈ [0, 1], Σj x̃ij = 1 produits scalaires (matrices de Gram) : x̃i = xi / √(Σj xij²), ‖x̃i‖ = 1

Exemple : classification de signaux

  • Détection de motifs indépendamment de l’échelle : normalisation par individu (min-max), somme à 1 (signaux positifs), somme des carrés à 1, somme à 0…
  • Invariance en translation (ou pas, selon la nature des informations discriminantes) : calcul des moyennes, écarts-types ; FFT, PSD.

Normaliser chaque signal

Deux formes de signaux (une bosse / deux bosses), avec des amplitudes et des niveaux de base très différents. Un plus proche voisin peut-il retrouver la forme ? Prédis : quelles normalisations suppriment le niveau de base et l’amplitude ?

Tes notes« Pour : obligatoire pour les entrées de réseaux de neurones. Contre : sert à rien pour les arbres et le gradient boosting ; perd une part d’information directe. » Précisions : pour les réseaux de neurones c’est très fortement recommandé (descente de gradient sensible aux échelles) plutôt qu’« obligatoire » ; les arbres ne comparent que l’ordre des valeurs d’une colonne, donc une transformation croissante de chaque colonne ne change rien (voir laboratoire) ; on « perd » l’échelle absolue (une valeur de 500 € ou de 5 000 € n’est plus visible). « Normaliser les lignes : texte, séries temporelles » : c’est la normalisation par individu ci-dessus.

9Conclusion : approche standard en ML

  1. Traitements = interprétation des informations métier / expert.
  2. Batteries de tests classiques pour estimer les performances attendues : normalisation standard ; modèles linéaires + forêts ; validation croisée ou autre selon les cas.
  3. Optimisation (idéalement automatisée ou semi-automatisée) : feature engineering, grid-search, ensembling.

Beaucoup d’outils existent en scikit-learn ⇒ maîtrise + documentation. Lorsqu’il manque un outil ⇒ penser intégration (l’insérer dans le cadre de scikit-learn).

Complément : à quoi ressemble une chaîne

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score

num = Pipeline([("imp", SimpleImputer(strategy="median")), ("norm", StandardScaler())])
cat = OneHotEncoder(min_frequency=6, handle_unknown="infrequent_if_exist")
pre = ColumnTransformer([("num", num, cols_num), ("cat", cat, cols_cat)])
model = Pipeline([("pre", pre), ("clf", RandomForestClassifier())])
scores = cross_val_score(model, X, y, cv=5)     # les statistiques sont recalculées dans chaque pli

L’intérêt du pipeline : moyennes, médianes, écarts-types et catégories sont calculés sur l’apprentissage de chaque pli seulement, jamais sur les données de test (évite la fuite).

10Pièges à éviter

  • Une chaîne « ? » dans une colonne numérique la transforme en texte : déclarer les valeurs manquantes à la lecture.
  • La moyenne est tirée par les valeurs aberrantes et par les sous-populations ; la médiane est plus robuste ; le plus proche voisin utilise les autres colonnes.
  • Supprimer les lignes incomplètes peut retirer une grande part des données.
  • Coder une variable catégorielle par 0/1/2 crée un ordre inexistant : utiliser le one-hot.
  • Target encoding sans précaution : fuite de la cible dans les variables explicatives.
  • Calculer moyenne, écart-type, catégories… sur toutes les données avant la validation croisée : fuite ; les calculer dans chaque pli (pipeline).
  • Normaliser ne sert à rien pour les arbres et le gradient boosting ; c’est important pour les modèles à distances (plus proches voisins, SVM à noyau) et à gradient (réseaux).
  • La normalisation par individu (ligne) dépend de la nature des données ; vérifier qu’elle ne supprime pas l’information discriminante (un niveau moyen peut être discriminant).
  • Un classifieur linéaire ne peut pas apprendre un damier sans colonnes ajoutées adaptées (interactions).
