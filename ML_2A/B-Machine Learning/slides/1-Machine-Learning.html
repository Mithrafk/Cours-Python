Selon le cadre, il y a différents algorithmes, différentes évaluations, différentes données et différents coûts. Une « nouvelle donne » : Amazon Mechanical Turk, qui permet de faire étiqueter des données par des humains à bas coût.

Grandes familles de problèmes supervisés

  • Classification : prédire une catégorie (une frontière sépare les classes).
  • Régression : prédire une valeur. Interpolation entre les points connus, ou forecasting (extrapolation au-delà).
  • Ranking : ordonner des éléments (documents pertinents en tête).
  • IA générative (la diapo ne met qu’un « ? ») : à titre de complément, à partir d’une suite d’éléments X, prédire l’élément suivant Y.

Très nombreuses applications, mais peu de problématiques générales : c’est ce qui rend l’étude de quelques méthodes rentable.

2Chaîne de traitement et évaluation

Identifier les entrées, les sorties et l’évaluation. Un jeu de données avec sa supervision (exemples étiquetés « verte » ou « rouge ») alimente l’apprentissage, qui produit un classifieur. Pour une nouvelle pomme, l’inférence donne une classe ; l’évaluation mesure la qualité du classifieur.

En plus concret : une extraction de caractéristiques (diamètre, texture, niveau de rouge, niveau de bleu…) produit une matrice X (une ligne par exemple, une colonne par caractéristique) et un vecteur de supervision Y ∈ {−1, 1}. Le modèle le plus simple est linéaire : f(x) = Σj αj xj. Deux leviers : sélectionner les bonnes colonnes, ajouter des colonnes intéressantes (calculs, sources de données externes).

L’évaluation est aussi importante que le modèleModèle sans mesure de performance : pas de sens. Modèle avec une performance fausse : danger. Modèle avec une performance basse : difficile à vendre. L’analyse des performances mène au modèle v2.

« 82 % de bonnes réponses » : c’est bien ?

Ça dépend de ce que ferait un modèle nul qui répond toujours la classe la plus fréquente.

Tes notes« Une performance de 82 % n’est pas toujours bonne : ça dépend de l’endroit où on l’applique et du jeu de données. » Exact. L’exemple de tes notes (82 % à gauche, 18 % à droite, on décide toujours gauche) donne 82 % de bonnes réponses avec un modèle nul. Le bon réflexe : comparer à ce modèle de référence (« baseline »).

4Arbres de décision

Notations

Un exemple xi = (xi1, …, xid) ∈ 𝒳 (souvent ℝd) ; une caractéristique Xj (continue, ordinale ou discrète) ; X = {x1, …, xn} ; supervision Y = {y1, …, yn}, yi ∈ {0, 1} ou {−1, 1}. Objectif : trouver f : 𝒳 → Y dont la prédiction sur de futurs exemples soit la plus précise possible.

Principe et algorithme

Présenter une instance à la racine ; un nœud = un test sur une variable ; une branche = le résultat du test ; une feuille = l’étiquette. L’apprentissage est un algorithme glouton, top-down :

  1. Initialisation à la racine avec tous les exemples.
  2. Si le nœud n’est pas pur : trouver la meilleure variable Xj et le test associé ; créer un fils par résultat de test ; faire « tomber » les exemples dans le fils correspondant.
  3. Sinon : transformer le nœud en feuille.

Choisir la meilleure variable : l’entropie

H(X) = − Σi P(X = xi) log P(X = xi) entropie ↗ = désordre ↗ ; entropie nulle = pas d’aléa = classification parfaite Cas binaire : H(Y) = − p₊ log p₊ − p₋ log p₋ Pour un test T : H(Y|T) = (|X⁽¹⁾|/|X|) H(Y⁽¹⁾) + (|X⁽²⁾|/|X|) H(Y⁽²⁾) Gain d’information : I(T, Y) = H(Y) − H(Y|T) → à maximiser ⇔ minimiser H(Y|T)
  • Variable discrète (Xj ∈ {A, B, C}) : l’ensemble se divise en 3, calcul aisé.
  • Variable continue : il faut tester toutes les valeurs de coupure : ordonner les valeurs de Xj, calculer H(Y|Xj) pour chaque coupure, garder la meilleure. La courbe « entropie vs seuil » a typiquement un creux.

Trouve la meilleure coupure

Le jeu de la diapo 11 : la classe rouge est en haut (X₂ > 6) ou à gauche (X₁ ≤ 3). Prédis : quelle variable et quel seuil donnent le plus grand gain à la racine ? Vérifie avec la courbe.

Laisse l’arbre pousser

L’algorithme glouton applique la recherche de la meilleure coupure à chaque nœud. Prédis : combien de niveaux faut-il pour ce jeu propre ? Que se passe-t-il quand on ajoute du bruit dans les étiquettes ?

ComplémentLa diapo 16 demande : « Comment aborder des problèmes de régression avec des arbres ? » Réponse usuelle : la feuille prédit la moyenne des y de ses exemples, et le critère de coupure n’est plus l’entropie mais la réduction de la variance (erreur quadratique).

Approche ancienne (systèmes experts, C4.5), mais toujours d’actualité : Random Forest, XGBoost, CatBoost.

Tes notes« Plus efficace de combiner des décisions simples : discriminer selon une seule variable explicative. » Oui, chaque nœud est un test simple sur une seule variable, l’arbre entier en combine beaucoup. Les critères entropiques se calculent par des algorithmes récursifs efficaces (l’algo glouton ci-dessus).

5Approches ensemblistes

La diapo 25 se contente de citer bagging, boosting, Random Forest, XGBoost (le cours de sélection de modèles y revient). Idée commune : au lieu d’un seul modèle, en entraîner plusieurs puis voter (ou faire la moyenne). Le tableau qui suit est un complément, à partir de tes notes.

Bagging / forêt aléatoireBoosting (AdaBoost, gradient boosting, XGBoost)
EntraînementLes arbres sont entraînés indépendamment (donc parallélisables), chacun sur un échantillon tiré avec remise ; en forêt aléatoire, chaque coupure ne regarde qu’un sous-ensemble tiré au hasard de variablesLes arbres sont entraînés l’un après l’autre : chaque nouvel arbre se concentre sur les erreurs des précédents

Un arbre, une forêt, du boosting

Mêmes données bruitées, trois méthodes. Augmente le nombre d’arbres T. Prédis : l’arbre seul sur-apprend-il ? La frontière de la forêt est-elle plus lisse ?

Tes notesTrois précisions. (1) « Un bon modèle qu’on duplique et dont on moyenne les résultats » : dupliquer le même arbre ne change rien ; le gain vient de la diversité (échantillons et variables différents). (2) « Tous les échantillons mais des variables différentes » : pour la forêt, chaque arbre voit un échantillon tiré avec remise ; les variables tirées au hasard interviennent à chaque coupure. (3) « Le boosting = base de la forêt mais pas vraiment aléatoire » : le boosting n’est pas une forêt biaisée ; c’est une famille séquentielle. Ton intuition sur le tirage biaisé vers les erreurs correspond à AdaBoost (les poids des exemples mal classés augmentent) ; gradient boosting et XGBoost corrigent, eux, l’erreur résiduelle.

6SVM et noyaux

Modélisation générique d’un phénomène

  1. Identifier la cible Y (rendement agricole, diagnostic médical, détection d’anomalies…) et les variables descriptives X.
  2. Choisir une modélisation : linéaire, non linéaire… ; ex. f(x) = Σj xj wj.
  3. Choisir une fonction de coût : moindres carrés, charnière, entropie croisée… ; ex. 𝓛 = Σi (f(xi) − yi)².
  4. Optimiser le coût : trouver les paramètres optimaux w*.

ProblèmeLe risque empirique (sur les données d’apprentissage) n’est pas le risque en généralisation : d’où le besoin d’une évaluation robuste (section 8).

La perte charnière (hinge)

yi ∈ {−1, 1} 𝓛 = Σi=1..n (1 − yi f(xi))+, (a)+ = max(a, 0) Forme de la décision (duale, par rapport aux points d’apprentissage) : f(x) = Σj=1..napp wj · k(x, xj) Régularisation : 𝓛 = Σi (1 − yi f(xi))+ + C ‖w‖²
  • Noyau k : linéaire (produit scalaire), polynomial, gaussien k(xi, xj) = exp(−‖xi − xj‖² / 2σ²)… Il permet une frontière non linéaire.
  • Vecteurs supports : la décision ne repose que sur les points sur et dans la marge, c’est-à-dire dans la zone de coût non nul (sur la diapo linéaire : seulement 2 points).
  • Deux cas : séparable et non séparable.

ComplémentRéponse à « quelle différence avec les moindres carrés ? » : la charnière ne coûte rien aux points bien classés au-delà de la marge (y f ≥ 1), alors que les moindres carrés pénalisent aussi un point « trop bien classé » (y f = 3 coûte (3 − 1)² = 4). Réponse à « réflexion sur les cas extrêmes » pour C : avec la forme de la diapo, C → 0 supprime la régularisation (on colle aux données, risque de sur-apprentissage) ; C → ∞ force w → 0 (sous-apprentissage).

Attention au sens de CDans la diapo, C multiplie la régularisation. Dans scikit-learn (SVC(C=…)) c’est l’inverse : C multiplie la perte, donc un C grand = peu de régularisation.

Le SVM de la diapo 21

Perte charnière + C‖w‖² sur f(x) = Σ wj k(x, xj), entraîné dans ta page. Prédis : que devient la frontière quand σ devient très petit ? et quand C devient très grand ?

Tes notes« f(x) = w·X (pondération linéaire), puis f(x) = Kx·w avec un noyau : modèle non linéaire, meilleur que le linéaire dans certains cas ; ce qu’il faut régler, c’est le noyau (lois gaussiennes, polynomiales…) ; gaussien réglé vs gaussien trop faible. » Oui : et le réglage du noyau (σ) est un hyperparamètre, comme C (voir fiche « Sélection de modèles »). Un σ trop petit fait des îlots autour de chaque point : c’est du sur-apprentissage.

Conclusions sur les SVM

  • Méthode de référence des années 90 et 2000 ; beaucoup de noyaux pour différents types de données (graphes, images…).
  • Initialement de la classification (SVM, SVC) ; extension à la régression (SVR).
  • Problème majeur de passage à l’échelle : complexité en O(n²) au mieux, souvent O(n³) ou O(n⁴).

7Du binaire au multi-classe

Beaucoup de classifieurs sont binaires (dont les SVM), beaucoup de problèmes ont plusieurs classes. Un-contre-tous (one-against-all) : pour K classes, on apprend K classifieurs séparément, sur toutes les données (la classe k contre toutes les autres). Le vecteur w devient une matrice d × K. Décision : k* = arg maxk fk(x) (« quelle classe veut le plus l’échantillon ? »).

Critère de rejetSituationQue faire
Rejet en distanceAucun fk(x) > 0,5 : « pas de foyer »Mettre dans la classe de score maximal, ou ne pas traiter (un expert prend le relais)
Rejet en ambiguïtéPlusieurs fk(x) > 0,5Fixer des seuils, ou rejeter

Un contre tous, avec rejet

Trois classes, trois régressions logistiques. Change le seuil et regarde les zones grises (aucune classe) et hachurées (plusieurs classes) apparaître.

Tes notesTon idée est la bonne : le rejet coûte du travail humain, mais seulement sur quelques points. Le modèle a de bons scores là où il décide, et l’expert traite le reste, ce qui donne un système acceptable dans son ensemble. (Rejet en ambiguïté : plusieurs classes au-dessus du seuil, pas seulement « plus de deux ».)

8Évaluer honnêtement

Règle d’orL’évaluation est aussi importante que l’apprentissage ! Évaluer sur les données d’apprentissage (celles qui ont servi à régler les paramètres) = tricherie et surestimation des performances. Évaluer sur des données vierges = OK.

  • Découper les n exemples en jeu d’apprentissage et jeu de test. Problème de la répartition entre apprentissage et test.
  • La validation croisée : K itérations ; à chaque itération, une partie sert de test et les autres d’apprentissage ; on obtient K modèles et K performances (Perf 1, …, Perf K).

Mesurer la vraie performance

Ici la vraie performance est connue : elle est mesurée sur 2 000 nouveaux points. Prédis : quelle estimation (apprentissage, test, validation croisée) s’en approche le plus ? Que change la présence de réplicats ?

Tes notes« Comment couper ? Penser à mélanger, car les données sont peut-être ordonnées. » Oui. « Si 1 à 2 % du jeu est dans la catégorie B, on pourrait la perdre du train ou du test » : on garde alors les proportions de chaque classe dans chaque morceau (stratification, complément). « Jeu trop petit ⇒ validation croisée : train et test sur plusieurs itérations en changeant à chaque fois le découpage. » « Fuite de données : on teste sur un jeu qui contient, parfois sans le savoir, des données du train ; par exemple des réplicats biologiques, des données presque identiques mais dans des pots différents, mélangés au hasard. » Solution : découper par groupe (tous les réplicats d’un même individu du même côté). Ce dernier point est un développement de ta part, la diapo ne le traite pas.

Cas déséquilibrés (anomalies, fraudes, entités dans les textes…) ⇒ nouvelles métriques, nouvelles procédures : voir la fiche « Sélection de modèles » (« prochain cours »).

9Mise en pratique avec scikit-learn

scikit-learn propose des modèles « sur l’étagère » (supervisé, non supervisé, estimation de densité…), des métriques, des pré-traitements et des chaînes, parallélise les calculs (n_jobs), et permet d’y insérer ses propres outils.

from sklearn import svm, linear_model, naive_bayes mod = naive_bayes.GaussianNB() # création d'un modèle bayésien naïf mod.fit(Xapp, Yapp) # apprentissage sur les données d'apprentissage yhat = mod.predict(Xtest) # inférence : un vecteur (n_test,) yhat = mod.predict([Xtest[0]]) # un seul exemple : encore une liste d'exemples yhat = mod.predict_proba(Xtest) # une matrice (n_test, nb_classes)

Complément : les questions de la diapo 29Quelle dimension ? predict renvoie un tableau de forme (n_test,) ; predict_proba, un tableau (n_test, n_classes) : une probabilité par classe. Pourquoi [Xtest[0]] ? scikit-learn attend toujours un tableau 2D (exemples × caractéristiques) ; Xtest[0] est un vecteur 1D, alors que [Xtest[0]] est un tableau à une ligne. Taux de bonne classification : accuracy_score(Ytest, yhat) ou mod.score(Xtest, Ytest). Passer à un arbre : remplacer GaussianNB() par tree.DecisionTreeClassifier(criterion="entropy") ; l’introspection se fait avec tree.export_text ou tree.plot_tree. Les autres lignes ne changent pas : c’est l’intérêt de l’interface commune.

10Pièges à éviter

  • Une exactitude ne se lit jamais seule : comparer à la classe majoritaire.
  • Évaluer sur les données d’apprentissage : surestimation systématique.
  • Découper sans mélanger des données ordonnées, ou avec une classe rare mal répartie (tes notes).
  • Réplicats répartis entre apprentissage et test : fuite de données (tes notes).
  • Le C des SVM change de sens entre le cours (régularisation) et scikit-learn (perte).
  • Dupliquer un même arbre ne sert à rien : il faut de la diversité (bagging) ou une correction séquentielle (boosting).
  • Un arbre sans limite de profondeur apprend le bruit (feuilles pures = mémorisation).
  • Un SVM à noyau gaussien avec σ trop petit : des îlots autour de chaque point d’apprentissage.
  • Un-contre-tous : prévoir le cas « aucune classe » et le cas « plusieurs classes ».
  • Les SVM ne passent pas à l’échelle : O(n²) au mieux.
